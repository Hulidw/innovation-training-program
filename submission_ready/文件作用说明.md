# 项目文件作用说明

项目名称：基于动态参数分配的 LoRA 大语言模型高效微调优化方法

## 一、核心程序

| 文件 | 作用 | 是否需要运行 |
|---|---|---|
| `dynamic_lora.py` | 项目核心算法。实现 LoRA 层重要性评估、动态 rank 分配和参数更新。 | 通常由其他训练程序调用 |
| `simple_train.py` | 最简本地演示程序，用小型网络快速验证动态 LoRA 是否能运行。 | 可以直接运行 |
| `experiment.py` | 对比固定 LoRA 和动态 LoRA 的实验程序，记录损失和训练速度。 | 云端实验时运行 |
| `train.py` | 较完整的训练入口，后续接入真实大语言模型时使用。 | 按需运行 |
| `cloud_qwen_experiment.py` | 云端 Qwen2.5-0.5B-Instruct 对比脚本，比较固定 rank LoRA 和动态 rank LoRA。 | 云端 GPU 上运行 |
| `gpu_smoke_test.py` | GPU 环境检查程序，确认 CUDA、PyTorch 和显卡是否正常。 | 换电脑或接云端时先运行 |

## 二、配置和运行文件

| 文件 | 作用 |
|---|---|
| `config.yaml` | 训练步数、学习率、rank 等参数的集中配置文件。 |
| `requirements.txt` | 项目依赖的 Python 软件包列表，用于安装环境。 |
| `run_demo.ps1` | Windows 一键运行本地演示的 PowerShell 脚本。 |
| `.gitignore` | Git 版本管理的忽略规则，不影响项目运行。 |

## 三、比赛材料

| 文件或文件夹 | 作用 |
|---|---|
| `README.md` | 项目简介、安装方法和运行命令。 |
| `技术方案.md` | 项目原理、创新点、算法流程和实验计划。 |
| `提交清单.md` | 比赛提交材料检查清单。 |
| `演示视频脚本.md` | 录制项目演示视频时参考。 |
| `答辩PPT大纲.md` | 制作答辩 PPT 时参考。 |
| `云端实验说明.md` | 明天连接云端后安装环境、运行实验和保存结果的说明。 |
| `云端Qwen实验说明.md` | Qwen2.5-0.5B-Instruct 的专用云端运行命令和结果判断方法。 |
| `generate_submission.py` | 自动整理代码、文档并生成技术方案 PDF。 |
| `submission_ready/` | 已整理好的待提交材料目录。 |
| `submission_ready.zip` | `submission_ready` 的压缩包，可上传比赛系统。 |

## 四、可清理项目

| 文件或文件夹 | 说明 |
|---|---|
| `dynamic_lora_project/` | 旧的重复项目副本。根目录文件是当前主要版本。 |
| `__pycache__/` | Python 自动生成的缓存文件夹，删除后不影响项目。 |
| `runs/` | 实验输出目录。正式云端实验后可用于保存日志和结果。 |

## 五、常用命令

检查 GPU：

```powershell
python gpu_smoke_test.py
```

运行本地小演示：

```powershell
python simple_train.py --steps 100
```

运行对比实验：

```powershell
python experiment.py
```

重新生成提交材料：

```powershell
python generate_submission.py
```

## 六、建议使用顺序

1. 运行 `gpu_smoke_test.py` 检查云端 GPU。
2. 运行 `simple_train.py` 确认程序能启动。
3. 运行 `experiment.py` 进行正式对比实验。
4. 将云端结果、曲线和指标补充到技术方案中。
5. 运行 `generate_submission.py` 重新生成提交包。
